# React Migration Brief

> Generated by Claude Code using Opus 5 in xhigh effort mode.

Convert this Vite + Vue 3 SPA to Vite + React while preserving pixel-identical
output. This is a design-fidelity project: the visual reference suite is the
acceptance gate, not a nice-to-have.

## Target stack

Vite + React. **Not Next.js.** The site is a single static page with no routing,
no server rendering, and no data fetching at runtime. Next would add a framework
layer that this project never exercises, and it would change the Vercel
deployment shape. Staying on Vite keeps the build, the deploy, and `vite.config.js`
essentially as they are, and keeps the diff limited to the component layer.

Swap `@vitejs/plugin-vue` for `@vitejs/plugin-react`. Keep `yaml` and `webamp`.

## Do not change

These are framework-agnostic and must survive the migration untouched:

- `src/content/site.yaml` — content source of truth.
- `src/content/loadContent.js` — parses YAML at build time via `?raw`.
- `src/content/validateContent.js` — hand-written validator that throws on bad
  content. Plain JS, no Vue. Keep as-is.
- `src/styles/reference.css` (2,343 lines) and `src/styles/runtime.css` (470
  lines) — hand-tuned global CSS. **Keep them global.** Do not convert to CSS
  Modules, styled-components, or Tailwind. Class names in these files are load
  bearing and are matched by the visual reference suite.
- `src/styles/palette.js`
- `public/assets/**`, `public/music/**`
- `tools/**` — montage and hero processing scripts, unrelated to the frontend.
- `popcorn-player.wsz` — imported via `?url`, which works identically in React.

Vue SFC `<style scoped>` blocks (e.g. in `MerchEmptyState.vue`) must be preserved.
Move each into a colocated plain `.css` file imported by its component, and
**manually replicate the scoping** by keeping the existing BEM-ish class names,
which are already effectively unique (`.merch-empty__headline-accent` etc.).
Do not introduce a scoping mechanism that rewrites class names.

## Acceptance gate

Run in this order:

1. `npm run test:content` — must pass unchanged.
2. `npm run build` — must succeed.
3. `npm run test:interaction` — slider and form behavior.
4. `npm run test:visual` — **do not run without explicit approval from the repo
   owner.** This compares against committed reference screenshots in
   `tests/visual/reference/` at 1280x800, 1440x900, 390x844, and 768x1024.

The visual suite is the real definition of done. A migration that builds and
renders but shifts type or spacing has failed.

## Component inventory

19 components in `src/components/` plus `src/App.vue`. Notes on the ones with
real behavior:

**`App.vue`** — Holds a `matchMedia('(max-width: 767px)')` listener that swaps
between `DesktopExperience` and `MobileExperience`, and computes CSS custom
properties (`--color-heading-outline`, `--heading-outline-width`) from content
onto the root `<main>` style. Becomes
`useState` + `useEffect` with the same listener add/remove lifecycle. Note the
`typeof window !== 'undefined'` guard is already present; keep it.

**`TopPickRelease.vue`** — The most intricate file, but it ports cleanly because
Webamp is not a Vue component. It:
- dynamically imports `webamp` and mounts it into a ref'd DOM node
- uses a `generation` counter to guard against async races when the variant
  changes mid-load — **this pattern must survive**, it is the fix for a real bug
- disposes the instance (`stop()` then `dispose()`) on unmount and on variant change
- runs a `ResizeObserver` that scales the 550x232 native player via a CSS
  transform and sets the frame height to match
- blocks the Webamp context menu with a capture-phase `contextmenu` handler
- renders desktop and mobile variants, with `isActiveVariant()` deciding which
  instance actually mounts so two Webamps never run at once

Map to a single `useEffect` with a cleanup function; keep the generation guard as
a `useRef` counter. Under React 18 StrictMode the effect runs twice in dev — the
dispose path must be correct or you will get two players. Consider leaving
StrictMode off initially, then enabling it to shake out lifecycle bugs.

**`MobileSlider.vue`** — Owns active slide state, dots, arrows, keyboard nav,
throttled wheel handling, touch gestures, and per-slide `aria-hidden` + `inert`.
The `inert` attribute needs `inert={condition ? '' : undefined}` in React, not a
boolean. Accessibility labels come from `content.accessibility` with
`{current}`/`{total}` interpolation.

**`ResponsiveImage.vue`** — Builds `srcset` by joining `image.sources[]` as
`${src} ${width}w`. Uses `inheritAttrs: false` plus `v-bind="attrs"` so callers
can pass through `class`/`loading`; in React this is just `{...rest}` props.
`sources` and `sizes` are both optional — the fallback to a plain `<img>` must
be preserved, it is what will let CMS-uploaded images work later.

**`AppLink.vue`** — Renders optional links; adds `rel="noopener noreferrer"`
when `target="_blank"`. Handles a null `url` by rendering non-link markup.

**`SectionHeading.vue`** — Renders display headings with configurable SVG
outlines driven by the theme custom properties. Check the generated SVG markup
carefully against the reference screenshots; attribute-order and whitespace
differences in inline SVG can shift rendering.

**Empty states** (`MerchEmptyState.vue`, `ShowEmptyState.vue`) — Currently
rendered because `sections.merch.items` and `sections.upcoming_shows.items` are
both `[]`. Keep the conditional that chooses between the empty state and the
populated list; a CMS will fill those arrays shortly.

## Sequencing

Do the React conversion **alone**, on its own branch, and land it green against
the visual suite before touching anything else. A CMS integration (Sanity) is
planned next, and it will move `sections.merch.items[]` and
`sections.upcoming_shows.items[]` out of YAML. Do not attempt both at once —
debugging a pixel regression is hard enough without a second variable.

## After the migration

Add `@vercel/analytics` and mount `<Analytics />` from `@vercel/analytics/react`
in the root component.
